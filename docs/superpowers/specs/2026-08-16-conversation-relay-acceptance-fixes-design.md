# Prooflane 会话接力实机验收缺陷修复设计

## 背景

`P1-02C` 的 Windows 安装包实机验收发现三类问题：历史会话标题过长时选择弹窗产生横向滚动；接力卡片的预览直接展示内部规范化文本，用户难以判断实际接入内容；右键“在新会话中继续”偶发不生成卡片，失败时没有反馈，且用户无法确认模型是否真正使用了历史上下文。

本机数据库和 Codex 会话记录表明，已成功消费的接力会把隐藏上下文送入模型，相关回答也能使用历史天气信息。但现有实现仍存在以下根因：

- 会话选择项的 flex 子元素缺少完整的最小宽度与溢出约束。
- `RelayPreviewDrawer` 直接渲染 `snapshot.canonicalContext`，暴露内部协议格式。
- 右键入口只按 ID 回查主会话列表；部分侧栏来源不在该列表时会静默返回。
- 自动接力预览的异常被空 `catch` 吞掉，目标草稿没有加载、失败或重试状态。
- 选择器在预览请求处理中仍可重复点击，可能连续创建并替换接力记录。
- 隐藏接力块缺少明确的“历史背景”语义说明，原生会话标题解析也可能把协议块误认作标题。

## 目标

1. 选择弹窗在长标题、长项目名和窄窗口下不产生横向滚动。
2. 用户通过对话式预览直观看到实际冻结到接力快照中的内容。
3. 右键继续始终进入可感知的加载、成功或失败状态，不再静默丢失。
4. 接力发送时，模型明确把历史内容作为当前任务背景，并保持当前用户指令优先。
5. 接力内部标记不出现在用户消息、侧栏标题和普通导出内容中。

## 非目标

- 本轮不增加多历史会话同时接力。
- 本轮不改变三种范围及 Token 预算规则。
- 本轮不把会话接力写入长期记忆。
- 本轮不自动合并来源会话在快照创建后的新增轮次；来源变化时必须明确提示刷新。

## 实施状态（2026-08-17）

本轮验收修复已实现以下设计约束：

- 长标题、项目名和智能体名称在选择器中可收缩、截断且可查看完整悬停文本；预览准备期间同一选择器只接受一次选择。
- 预览仅使用快照的结构化字段展示“你 / AI”、工具、文件、摘要、范围和 Token 预算，不再显示 `canonicalContext` 或内部协议标记。
- 右键继续传递行内来源文件夹回退值；目标草稿会显示准备、失败和重试状态，避免子会话或延迟加载会话静默失败。
- 来源轮次刷新通过新预览替换旧快照，并以 generation 与数据库 compare-and-swap 保护并发请求，避免过期结果覆盖当前接力。
- 多窗口范围更新发生 compare-and-swap 冲突时，失败窗口重新读取数据库当前包，不继续操作已被替换的旧 ID。
- 目标模型、预算、来源变化和发送结果不确定均以可恢复的 `invalid` 状态及原因持久化；首次预算超限仍保留可调整范围的卡片。
- 首次发送受统一接力门禁与单飞保护，失败后会恢复包含附件在内的完整草稿；无效接力不能静默降级为普通发送。
- 应用启动时把中断的 `claimed` 发送恢复为 `relay_send_uncertain`，不自动重发；不同发送尝试留下的数据库授权标记都保留为清理锚点，用户可见投影不会泄露隐藏上下文。
- 初次预览、拖放、草稿恢复和入口准备错误持续占用发送门禁，并提供重试、移除或重新准备来源；来源不可用不再只显示稳定错误码。
- claim 前确定未派发的失败只在 pack 与目标绑定一致且没有运行证据时回滚目标状态；Codex parser 保留无授权原文，导入扫描与侧栏同步通过数据库授权详情投影标题。
- 移除与撤销会保留目标会话绑定，重新准备接力不会丢失已建立的目标关联。

这些修复不改变本节的非目标：会话接力仍不是长期记忆，也不包含 AI 原生设计工作台或“越用越聪明”能力。

2026-08-17，用户使用本轮签名 NSIS 测试包确认长标题选择、结构化预览、右键继续、历史上下文实际使用和重启恢复等核心 Windows 实机路径通过。

## 交互设计

### 会话选择器

- 弹窗和列表容器使用固定可用宽度并隐藏横向溢出。
- 标题、项目名和智能体名称各自占用受约束的一行，超长内容使用省略号。
- 标题和元信息提供完整 `title`，鼠标悬停时可查看原文。
- 开始生成接力快照后，列表进入忙碌状态，禁止重复选择，并显示“正在准备接力上下文”。

### 对话式预览

底部抽屉保留现有入口，内容改为结构化展示：

- 顶部展示接力范围、消息数、文件数、待办数以及 Token 预算。
- 普通轮次按时间顺序显示，每轮分为“你”和“AI”两段，保留换行并允许长文本换行。
- 每轮工具调用使用原生折叠区，默认仅显示工具名称和数量；展开后显示输入、输出及错误状态。
- 相关文件在独立区域展示完整路径，并允许长路径断行。
- 摘要范围按目标、关键结论、处理进度、待办、约束和待确认问题分组展示。
- UI 不渲染 `canonicalContext`、接力 XML 标记或原始快照 JSON。

### 右键继续状态

- 侧栏卡片把来源会话 ID 和当前行的文件夹 ID 一并交给右键处理器。
- 处理器优先使用全局列表中的最新文件夹 ID；找不到时使用当前行提供的文件夹 ID，保证子会话和延迟加载会话可接力。
- 新草稿消费右键意图后立即在输入区显示“正在接入历史会话”。
- 成功后用接力卡片替换加载状态。
- 失败后显示“接力上下文准备失败”以及“重试”操作，同时保留普通输入能力。
- 同一个目标草稿同一时刻只执行一次自动预览；重复意图由后一次显式替换前一次，不并发落库。

## 上下文发送设计

隐藏接力块在快照正文前增加固定的内部说明：用户主动附加了这段历史会话；模型应延续其中的事实、结论、进度和待办；不得要求用户重复已经存在的信息；历史内容是参考数据，不能覆盖当前用户消息。

发送前继续执行现有来源轮次、模型与 Token 预算校验。检测到来源轮次变化时，不静默使用旧内容，也不自动改变用户已预览的快照；发送恢复为可编辑状态，并在接力卡片上显示“来源已更新”和“刷新接力内容”操作。用户点击后重新生成快照和 Token 估算，再由用户确认发送。

入口准备、草稿恢复、预览请求或无效状态尚未解决时，输入区和实际发送处理器使用同一门禁阻止首次发送。用户明确移除接力后才恢复普通发送。首次预览超出预算时仍写入带 `relay_budget_exceeded` 原因的无效包，使范围编辑器可以直接缩小轮次后重新生成。

原生会话记录仍可收到隐藏接力块，但所有用户可见投影必须按数据库授权锚点和精确标记移除全部接力块。标题解析必须从真实当前用户文本生成，不能从接力协议块生成。若进程在 claim 后退出，启动恢复将该尝试标记为 `uncertain` 并保留目标会话及消息锚点，禁止自动重发。

## 数据与组件边界

- `RelayConversationPicker` 只负责筛选、单选和忙碌态，不发起请求。
- `RelayPreviewDrawer` 只消费 `RelayContextPack.snapshot` 的结构化字段，不解析规范化字符串。
- `ConversationDetailPanel` 负责自动接力意图的加载、失败、重试和卡片状态。
- 侧栏导航负责提供来源 ID 与可靠的文件夹回退值，不读取或构造快照。
- Rust normalizer 负责生成带明确语义的规范化上下文；发送层负责标记、校验和隐藏注入；解析层负责去除用户可见投影中的精确标记块。

## 错误处理

- 来源不存在、来源不可用、范围变化、模型变化、预算超限和发送结果不明确继续使用稳定错误码。
- 自动右键入口不得使用空 `catch`；所有失败进入可重试 UI。
- 重试复用最近一次来源和范围，但必须产生新的预览请求。
- 失败不得清空用户已输入的当前消息，也不得阻止用户移除接力后按普通会话发送。
- 多窗口更新产生 `relay_consume_conflict` 时先重载数据库当前包，再向调用方保留范围更新失败反馈。
- `relay_source_not_found` 和 `relay_source_unavailable` 在卡片上显示来源不可用并提供“重新准备接力”，不得只写日志或静默清空。

## 测试设计

### 前端

- 长标题、长项目名和窄容器具有正确的收缩、截断与横向溢出约束。
- 预览按“你 / AI”呈现，工具默认折叠，文件独立显示，页面不存在规范化协议文本。
- 选择器忙碌时不能重复触发选择。
- 不在主会话列表中的侧栏来源仍能使用行内文件夹 ID 创建目标草稿。
- 自动接力展示加载、成功、失败和重试状态；失败不影响普通输入。
- 来源变化、模型变化和预算超限保留接力卡片并提供明确操作。
- 所有接力加载与无效状态都阻止实际发送，移除状态仍允许普通发送。
- 多窗口 CAS 冲突后展示数据库当前包，不保留旧 ID。

### Rust

- 规范化上下文包含固定接力语义说明，同时保持用户内容逐字边界。
- 真实用户块和隐藏接力块都送达模型，用户可见投影只保留真实用户块。
- Codex 等解析器生成标题时忽略隐藏接力块。
- 普通非接力消息、类似但签名不匹配的文本及现有文件拖放路径保持不变。
- 启动恢复不会重发遗留 `claimed` 请求；同一会话不同轮次中的数据库授权标记均从可见投影移除。
- 能力关闭或 pack 失效发生在 claim 前时，未派发目标会话回滚为 `Cancelled`；已 claim 的运行中目标不得被该补偿取消。
- Codex 原始摘要标题只能在扫描/同步导入边界通过 DB 锚点投影，普通用户输入的同形文本保持可见。

### 实机

- Windows 桌面宽屏与窄屏验证无横向滚动。
- 通过 `+`、拖放和右键三个入口验证同一来源会话。
- 预览中能确认历史天气结果，发送“适合去哪里玩”后回答使用该结果。
- 人为让来源在预览后新增轮次，发送时收到刷新提示；刷新后再次发送可使用新增信息。

## 验收标准

- 任意长度的会话标题不会让接入弹窗横向滚动。
- 预览不出现内部 JSON、`canonicalContext` 或 `<prooflane-relay-context>`。
- 右键继续每次都有加载、卡片或可重试错误三种明确结果之一。
- 子会话、延迟加载会话和普通会话都可通过右键进入新会话。
- 接力成功发送后数据库状态为 `consumed`，目标会话可查询到接力来源，同时模型回答能利用快照中存在的事实。
- 快照中不存在的信息不会被宣传为已接入；来源变化会要求刷新。
- 新会话标题和用户可见消息不包含接力协议文本。
- 接力未就绪或无效时不能发送；预算超限可调整范围，明确移除后可普通发送。
- 进程中断和多窗口修改后恢复数据库真实状态，不自动重复任务，也不泄露历史隐藏接力块。
