# DES-1A.3 场景查询、专业命中与视口裁剪设计

> 文档版本：1.0  
> 更新日期：2026-08-20  
> 状态：设计已确认，待实施计划与代码实现  
> 前置交付：`DES-1A.3` 基础 viewBox 导航、选择集与 SVG 框选

## 1. 目标

在现有 SVG 画布基础上建立渲染器无关的场景查询层，统一处理节点可见性、点命中、矩形框选和视口裁剪，为后续 CanvasKit/WebGL 主渲染提供稳定契约。

本阶段必须解决：

1. 点命中结果符合视觉层级，最上层节点优先。
2. 框选结果保持文档顺序，并过滤不可选节点。
3. 视口查询只返回与当前文档视口相交的可见节点。
4. 文档变更时索引可重建，视口变化不重建索引。
5. 100、1,000、10,000 节点场景具备可重复的正确性和耗时基准。

## 2. 非目标

本阶段不实现：

- CanvasKit 或 WebGL 主渲染切换。
- 吸附、对齐、分布、旋转和批量变换。
- 文字轮廓级、Path 级和笔画级精确命中。
- R-tree、四叉树等复杂空间索引的最终选型。
- Worker 渲染、缩略图、小地图和导出。

## 3. 核心契约

新增 `SceneIndex`，对外提供以下纯查询接口：

```ts
interface SceneIndex {
  readonly revision: string
  queryViewport(viewport: DesignBounds): string[]
  hitTestPoint(point: { x: number; y: number }): string[]
  hitTestRect(rect: DesignBounds): string[]
  dispose(): void
}
```

构造函数接收完整 `DesignDocument`，在文档 revision 变化时重建：

```ts
function createSceneIndex(document: DesignDocument): SceneIndex
```

所有返回值只包含节点 ID，调用方根据 ID 从文档映射节点。查询层不修改 DesignDocument，也不持久化 UI 状态。

## 4. 节点规则

### 4.1 可见性

- `visible === false` 的节点不进入可见查询和命中结果。
- `document`、`page` 节点不进入可选命中结果，但可以作为结构容器参与视口范围计算。
- `locked === true` 的节点可以被视口渲染，但不进入可选命中结果。
- 没有 `bounds` 的节点不进入几何命中和视口裁剪；仍保留在文档中供后续结构能力使用。

### 4.2 点命中

- 使用节点 `bounds` 的几何命中作为本阶段统一规则。
- 边界接触视为命中。
- 返回顺序为视觉层级从上到下：后出现在 `document.nodes` 的节点优先。
- 返回多个 ID，调用方可以实现深选、循环选择或调试展示；当前画布默认使用第一个 ID。

### 4.3 矩形命中

- 支持负向拖拽矩形。
- 边界接触视为相交。
- 返回顺序保持 `document.nodes` 原始顺序。
- 只返回可选节点，不返回 locked、hidden、document、page 节点。

### 4.4 视口查询

- 视口矩形支持负向宽高但内部先归一化。
- 返回所有与视口相交且 `visible !== false`、有 bounds 的节点。
- 视口查询保持文档顺序，确保 SVG/CanvasKit 绘制顺序稳定。
- 已选节点若位于视口外，不强制加入渲染列表；选择外框由画布按选中节点单独绘制，避免裁剪导致选择状态消失。

## 5. 索引实现策略

第一版采用可替换的线性索引：构建时生成轻量几何记录和 ID 映射，查询阶段遍历记录。这样优先固定行为契约和基准数据，避免在正确性尚未稳定时引入复杂空间树。

索引内部保留 `bounds`、`nodeIndex`、`selectable`、`visible` 和 `zOrder` 字段。后续可在不改变 `SceneIndex` 接口的情况下替换为网格、四叉树或 R-tree。

索引生命周期：

1. `document.revision` 或节点几何/可见性发生变化时由 React 宿主创建新索引。
2. 仅 viewport、zoom、pan 变化时复用同一个索引。
3. 组件卸载时调用 `dispose()`，第一版允许空实现，但接口必须存在。

## 6. SVG 接入

`DesignSvgCanvas` 改为通过 `SceneIndex` 获取 `visibleNodeIds`，只渲染视口相交节点；以下节点例外保留：

- 当前选中的可见节点，用于保证选区外框稳定。
- 正在拖拽的单节点，用于保证预览不因裁剪消失。
- 正在显示的框选矩形，不属于文档节点。

画布中的点击和框选使用 `SceneIndex.hitTestPoint`、`SceneIndex.hitTestRect`，移除组件内部重复遍历逻辑。现有 `selection.ts` 纯函数保留为底层几何规则或迁移到 scene-query 模块，避免出现两套边界定义。

## 7. 性能门禁

新增确定性基准测试，不以单次偶然耗时作为唯一结论：

- 场景：100、1,000、10,000 个矩形节点，固定网格布局和固定视口。
- 正确性：视口查询、点命中、框选结果与线性参考实现一致。
- 构建：索引构建时间记录为测试输出，不得出现数量级异常增长。
- 查询：单次 viewport、point、rect 查询均记录耗时；10,000 节点场景默认目标为 P95 小于 16ms，若 CI 环境不稳定则同时保留宽松告警阈值和结果一致性硬门槛。
- 内存：不引入节点对象深拷贝，不把完整 DesignDocument 复制到索引。

基准测试不得依赖真实浏览器、随机数或网络；使用固定种子/固定布局，保证本地和 CI 可重复。

## 8. 错误处理与兼容

- 空文档、无 bounds 文档和非法负尺寸不得抛出未捕获异常，查询返回空数组或按归一化规则处理。
- revision 不一致由宿主重建索引，不允许旧索引继续服务新文档。
- 旧的 `selectedNodeId/onSelectNode` 兼容接口继续保留到本阶段结束，内部统一转换为选择集。
- prototype/run 只读模式仍可使用视口裁剪，但不允许修改选择状态或节点。

## 9. 验收标准

- 点命中在重叠节点上返回视觉最上层节点作为第一项。
- 框选支持负向矩形、边界接触和锁定/隐藏过滤，结果顺序稳定。
- 视口变化不触发索引重建；文档 revision 变化会触发重建。
- 画布只渲染视口节点，选中节点和拖拽节点不会因裁剪消失。
- 100、1,000、10,000 节点固定场景测试全部通过；10,000 节点查询结果与参考实现一致。
- 全量 Vitest、目标 ESLint、`pnpm build` 和 `git diff --check` 通过。

## 10. 后续演进

本阶段完成后，`SceneIndex` 将作为 CanvasKit/WebGL 适配层的共同输入。只有在查询契约、选择语义和性能基准稳定后，才进入 CanvasKit 主渲染接入，避免渲染后端切换与几何规则变化同时发生。
